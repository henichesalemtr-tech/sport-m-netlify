# سجل القرارات المعمارية (DECISIONS — ADRs)

> قرارات مختصرة بصيغة: السياق ← القرار ← البدائل ← النتائج.
> **NOT VERIFIED:** القرارات انعكاس للكود المكتوب؛ لم تُختبر نتائجه تشغيليًا هنا.

## ADR-1: Next.js 14 Modular Monolith

- **السياق:** نظام لنادٍ/أكاديمية، فريق صغير، خادم محلي واحد، واجهة عربية SSR + API.
- **القرار:** تطبيق واحد Next.js (App Router) مقسم وحدات داخلية صارمة
  (route→service→repository) — `src/modules/*` + `src/app/api/v1/*`.
- **البدائل:** microservices (مبالغة)، Laravel/Django + SPA منفصل (نشر أعقد)،
  Express + React (فريقان تقنيان).
- **النتائج:** + نشر عملية واحدة، ذرّية مالية بسيطة، مشاركة مخططات Zod بين
  FE/BE. − الحاجة لانضباط داخلي لمنع تسرب المنطق بين الوحدات (يغطيه
  CONVENTIONS.md)، وscaling أفقي يتطلب sticky sessions أو جلسات DB (لدينا DB sessions أصلًا).

## ADR-2: Prisma + PostgreSQL

- **السياق:** حاجة ماسة لقيود متقدمة: EXCLUDE gist، فهارس جزئية فريدة، BIGINT،
  advisory locks، pg_trgm.
- **القرار:** PostgreSQL إلزامي للإنتاج + Prisma ORM، مع SQL خام
  (`prisma/raw-constraints.sql`) لما لا يعبر عنه Prisma.
- **البدائل:** MySQL (لا EXCLUDE ranges مكافئ عمليًا)، Drizzle/Knex (أقرب للـ SQL
  لكن أقل إنتاجية)، TypeORM.
- **النتائج:** + أمان استعلامات وإنتاجية وهجرات. − الهجرة الأولية يجب أن تُولَّد
  بمعرفة Prisma (انظر prisma/migrations/README.md)، وقيود EXCLUDE تعيش خارج
  إدارة Prisma المباشرة.

## ADR-3: BigInt بأصغر وحدة للمال

- **السياق:** أخطاء float المالية غير مقبولة (0.1+0.2≠0.3)؛ JS number غير آمن
  للمبالغ الكبيرة.
- **القرار:** كل المبالغ `BigInt` بأصغر وحدة (DZD×100) في القاعدة والكود؛
  واجهات API تستقبل نصوصًا عشرية وتعيدها نصوصًا؛ `shared/money` هو المدخل الوحيد.
- **البدائل:** DECIMAL عبر Decimal.js (أداء/تعقيد تسلسل)، float مع تقريب (مرفوض).
- **النتائج:** + دقة مطلقة، جمع/طرح بلا مفاجآت. − تسلسل JSON خاص (نصوص)،
  تقسيم يحتاج سياسة تقريب صريحة (اعتمدنا تقريب-لأسفل مرة واحدة في الخصم).

## ADR-4: Argon2id + جلسات في قاعدة البيانات

- **السياق:** كلمات مرور موظفين + قدرة على الإبطال الفوري + تدقيق.
- **القرار:** Argon2id (memoryCost≈19MB) للتجزئة؛ جلسات خادمية في جدول `sessions`
  (رمز مُجزَّأ SHA-256) مع كوكي httpOnly/sameSite=lax/secure، انتهاء خامل + مطلق.
- **البدائل:** bcrypt (أقدم/أضعف ضد GPU)، JWT بلا دولة (لا إبطال فوريًا، تسريب
  أسوأ)، Redis للجلسات (اعتمادية إضافية).
- **النتائج:** + إبطال per-device فوري، تدقيق دخول كامل. − استعلام DB لكل طلب
  (مقبول بحجم نادٍ)؛ **TOTP مُنفّذ الآن**: سر مخزّن مشفّرًا (AES-256-GCM بمفتاح من SESSION_SECRET) وتحقق زمني عبر otplib مع تدفق setup/enable/disable — لم يُختبر (يتطلب migration للعمود `totp_secret`)
  مفتوح: تخزين السر مشفرًا بـ APP_SECRET واعتماد otplib (موجود في الاعتماديات).

## ADR-5: next-intl + خط Cairo محلي (عربية RTL أولًا)

- **السياق:** المستخدمون عرب؛ self-hosted بلا اعتماد CDN؛ أرقام عربية/لاتينية قابلة للتبديل.
- **القرار:** next-intl (حاليًا `messages/ar.json`)، `dir="rtl"` + Logical Properties،
  خط Cairo مُضمَّن محليًا، الحقول الرقمية/البريد LTR داخل حقولها،
  `number.system` (arab|latn) إعداد.
- **البدائل:** react-i18next (أثقل مع App Router)، نصوص عربية صلبة (مرفوض — CONVENTIONS).
- **النتائج:** + إضافة لغة لاحقًا = ملف رسائل جديد. − كل نص جديد يحتاج مفتاح ترجمة.

## ADR-6: Self-Hosted بخط Cairo (لا SaaS)

- **السياق:** بيانات قاصرين ومالية حساسة، متطلبات خصوصية محلية، أندية بميزانية محدودة.
- **القرار:** النظام يُنشر على خادم النادي (Docker اختياري) — لا خدمات سحابية إلزامية.
- **النتائج:** + سيادة كاملة على البيانات، عمل دون إنترنت. − مسؤولية النسخ
  الاحتياطي/التحديثات على المالك (RUNBOOK).

## ADR-7: SQLite للتطوير فقط (fallback)

- **السياق:** مطور بلا PostgreSQL مثبت.
- **القرار:** المخطط يستهدف PostgreSQL حصرًا (datasource provider = postgresql).
  أي استخدام لـ SQLite هو حل تطويري مؤقت **يسقط معه**: EXCLUDE (تعارض الحصص)،
  الفهارس الجزئية الفريدة، advisory locks، pg_trgm ⇒ **ضمانات التزامن والقيود
  غير مطبقة**.
- **النتائج:** اختبارات التكامل المالية/التزامنية يجب أن تعمل على PostgreSQL
  حقيقي فقط (TESTING.md). لا يوجد provider switch في schema.prisma — التحويل
  يتطلب تعديل المخطط (غير موصى به).

## ADR-8: HTML→PDF عبر متصفح headless (للوصولات/التقارير)

- **السياق:** وصولات A4/80mm وتقارير PDF بتنسيق عربي RTL.
- **القرار (مخطط):** توليد HTML من قوالب النظام ثم تحويله بمتصفح headless
  (مثل Chromium عبر Playwright المثبت أصلًا للاختبارات) — بدون اعتماد مكتبة PDF
  عربية ناقصة.
- **البدائل:** pdfkit/jsPDF (دعم RTL/خطوط عربي ضعيف)، wkhtmltopdf (مهجور).
- **النتائج:** + دقة عرض RTL/خط Cairo. − يتطلب Chromium على خادم الإنتاج
  (موجود في صورة Docker إن استُخدم وضع E2E/PDF) — **التنفيذ الفعلي لمسار PDF
  يجب التحقق منه** (الوصولات الحالية تُعاد HTML عبر `/payments/[id]/receipt`).

## ADR-9: exceljs للتصدير

- **السياق:** تصدير تقارير كبيرة Excel/CSV مع عربية صحيحة.
- **القرار:** exceljs (streaming) + CSV يدوي مع BOM وتعقيم حقن الصيغ
  (`shared/export`).
- **البدائل:** xlsx/SheetJS (ترخيص)، CSV فقط (مرفوض 요구ًا).
- **النتائج:** + تدفق للصادرات الضخمة. − حجم اعتمادية أكبر.

## ADR-10: Worker/Cron داخل العملية (بدون Redis)

- **السياق:** مهام دورية (انتهاء اشتراكات، إشعارات، نسخ، تسوية) على خادم واحد.
- **القرار:** `scripts/worker.ts` يشغّل سجل `src/jobs` بحلقة زمنية أو `--once`
  عبر cron النظام؛ منع التكرار بأقفال `JobRun.lockKey` الفريدة في PostgreSQL
  (يومي/ساعي) + `recoverStaleJobs`.
- **البدائل:** BullMQ/Redis (اعتمادية وبنية إضافية)، Vercel Cron (لا يناسب self-hosted).
- **النتائج:** + صفر اعتماديات إضافية، أمان تشغيل مزدوج. − لا طوابير فورية/أولويات؛
  الجدولة دقيقة-على-الأكثر (حسب INTERVAL)؛ التوسع لأكثر من خادم يعمل لكن
  بدون توزيع ذكي للحِمل.

## ADR-11: SQL خام للقيود الخاصة (EXCLUDE/فهارس جزئية/REVOKE)

- **السياق:** Prisma لا يعبر عن EXCLUDE USING gist ولا الفهارس الجزئية WHERE
  ولا إدارة صلاحيات الأدوار.
- **القرار:** `prisma/raw-constraints.sql` يُطبق بعد الهجرة (يدويًا أو مدمجًا في
  نهايتها) + REVOKE يدوي على audit_logs لدور التطبيق.
- **البدائل:** كتابة المخطط كله SQL يدويًا (فقدان مزايا Prisma)، تجاهل القيود
  والاعتماد على الكود فقط (غير مقبول ماليًا/جدولةً تحت التزامن).
- **النتائج:** + ضمانات على مستوى القاعدة. − خطوة نشر إضافية يجب ألا تُنسى
  (موثقة في DEPLOYMENT/RUNBOOK/migrations README)، وملف SQL ليس idempotent
  كليًا (ADD CONSTRAINT بلا IF NOT EXISTS — انظر DEPLOYMENT §6).

## ADR-12: أرقام تسلسلية بقفل استشاري بدل SEQUENCE

- **السياق:** وصولات/حركات "بلا فجوات" لكل سنة مالية — SEQUENCEs تترك فجوات
  عند التراجع (rollback).
- **القرار:** قفل استشاري (advisory lock) بمفتاح السنة داخل المعاملة ثم
  `max(sequence)+1` + قيد فريد (fiscal_year, sequence).
- **النتائج:** + gapless مضمون. − نقطة تserialisation لكل سنة مالية (مقبولة
  بحجم نادٍ)، واعتماد على سلوك PostgreSQL.
